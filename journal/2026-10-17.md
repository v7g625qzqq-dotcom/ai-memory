### 本轮踩到的 4 个真 bug
1. **参数迁移顺序**（`normalizeParams`）：先用 `def` 补默认值会把新字段（如 `rOut`）先填上，导致「老存档无该字段」的迁移分支永远进不去。**必须先迁移、后补默认**。
2. **`CylinderGeometry(rx, ry, h)` 不是椭圆柱** —— 两个半径语义是「上底/下底」不是「X/Z」，传 (20,40) 得到圆台。正确做法：生成正圆柱后 `g.scale(1, 1, ry/rx)` 缩放顶点。
3. **螺旋扫掠 `spin` 未叠加** —— `buildScrewThread` 里螺旋角算了却没用，只用周向角取点，生成的是**一叠同心圆环**而非螺旋，且 `dir` 完全失效（改方向几何纹丝不动）。修：`angle = 2π*j/circum + spin`。
4. **`download()` 静默失败**（见上）。

- 判「几何是否变化」不能用 `Σx`（旋转对称恒等）、不能用 `Σ|z|`（镜像不变）、也不能取 ring 0（`spin=0`，与 `dir` 无关）；`positions` 是 `(x,y,z)` 三元组，取 `a[i+1]` 拿到的是轴向 y。**最终判据：取 ring i=16（spin≈±π/2 非对称）的顶点 x/z**。

## 追加：螺杆叶片去轴（林老板要 3D 打印推料螺杆）

### 需求
- 「不管怎么改外面的叶片都和里面的轴连不到一起」→ 根因：`taper` 锥度同时收缩叶片内径，而中心轴半径固定，一改锥度就脱开。
- 「把轴心去掉，后面自己加轴心，只要改叶片参数」

### 改动
- `auger`（螺杆）改名「**螺杆叶片**」，`buildAuger` 删掉 `mergeGeometriesSafe([flightG, shaftG])` 的中心轴，中心中空（实测半径<5mm 顶点数=0）。
- 参数 `shaft`（轴径）→ **`id`（内径/轴径）**，新增 **`thick`（叶片厚度）**，共 6 项：外径 / 内径(轴径) / 螺距 / 长度 / 叶片厚度 / 锥度%。
- **锥度只作用外径，内径恒定** —— 实测 taper=40% 时内径仍为10mm（改前是底部2mm/顶部10mm的锥形孔）。

### 关键 bug（新增第4 条铁律）
**`sweepHelical` 的 profile 径向偏移是「相对 rAt(t)」的，常量会随锥度一起变。**
内缘写成常量 `-(rOuter-rInner)` 时，锥度下基准半径漂移 → 内孔被拽成锥形。
修法：给 profile 的径向项支持函数 `(t)=>number` 表达**绝对半径**，内缘写 `(t)=> rInner - rOuter*(1-taper*(1-t))`；`buildSpring`/`buildFlight` 传常量不受影响。

### 旧存档兼容
老工程 `auger.params.shaft` → `normalizeParams` 自动映射到 `id`，数值沿用（老用户按 shaft 画的轴正好能插进新内孔）。

### 验证
v7.mjs 24/24 + v8.mjs 31/31 全绿，无回归。已同步桌面（1,796,340 字节）。

## 追加：对齐功能重做（valign.mjs 19/19 + v7 24/24 + v8 31/31 = 74/74）

### 交付
- **9 个对齐按钮**（X−/X居中/X+、Z−/Z居中/Z+、Y−/Y居中/Y+），语义对齐 Tinkercad：
  - 多选 → 贴到**选择集整体包围盒**对应位置
  - 单选 → 贴到**工作平面**（Y 用 plane.origin[1]，无平面则地面 0；X/Z 用原点 0）
- **等距分布** X/Y/Z（需≥3 个）：首尾锚定，中间按**空隙等分**
- **「落到地面」** 一键按钮
- 快捷键：`Ctrl+方向键` = 对齐，`Ctrl+⇧+方向键` = 分布；无 Ctrl 的方向键仍是微调

### 旧实现的两个实质缺陷（已修）
1. **居中用 `o.pos`（物体原点）而非包围盒中心** —— 几何中心不在原点的物体（手绘/SVG/旋转过的）必然算错。
2. **硬编码 `20` 作为对齐基准** —— 基准不可控。现改为 `selectionBounds()` 动态求。

### 本轮踩到的 2 个真 bug
1. **`o.pos` 是数组，`o.pos['x']` 字符串下标取到 undefined → 静默 NaN**。
   `Box3.min` 是 Vector3（字符串键 OK），`o.pos` 是数组（必须数字下标）——同一个 key 在两者上语义不同，混用不报错只是坐标不动。修：`const AXIS_INDEX = {x:0,y:1,z:2}`。
2. **等距分布的 gap 定义错了** —— 我原先按 `span/(n-1)` 推，**对象不等大时结果不均**（大物体旁间隙挤、小物体旁松）。
   正确是**空隙等分**：`(span - Σ各对象尺寸) / (n-1)`。实测 20/30/20 三个盒子，旧算法 gap=[55,95]，新算法 gap=[75,75]。

### 测试脚本自身的坑（连续 3 次把断言写错，浪费不少时间）
- 2.2「左对齐后整体宽度不变」——**断言本身荒谬**：左对齐的定义就是全部贴到最左，宽度必然变。
- 「所有对象位移量相同」——同理，左对齐时各对象位移必然不同。
- 「方向键后 min.y 应为 50」——实际微调按 snap=10 加一格变成 60，我断言没算步长。
- **教训**：断言要写「功能的定义」，不是「我以为的结果」。写完先手工推算一遍期望值再断言。
- 另：`meshes.get()` 后 `Box3.setFromObject()` 读到的是**移动前**的盒子（`setBoxEdge` 只改 `o.pos` 未同步 `mesh.position`）—— 若算法需要回读包围盒，必须先同步 mesh 位置。本轮改为不回读、直接用算好的厚度。

`window.__tclite` 现额外暴露：`syncAll` / `syncPanel` / `attachTransform` / `detachTransform` / `rebuild` / `alignSelection` / `distributeSelection` / `alignToGround` / `selectionBounds` / `objectById`。

## 第十二轮：框选（橡皮筋）+ 视口UI 遮挡诊断（v12.mjs 21/21，累计 147/147）

### 功能
- **框选**：空白处按住左键拖矩形，框住的实体被选中。
  Shift 拖 = 追加（橡皮筋变绿），Ctrl 拖 = 剔除（变红）。左键在 orbit 里本就禁用（LEFT: null），正好让给框选。

- 提交走 window 上的 `pointerup`（canvas 的 pointerup 是目标阶段，先于冒泡）。

### 本轮修的2 个真 bug
1. **`.boxsel-rect` 的 CSS 从来没写过**（`grep -c boxsel src/style.css` = 0）。

   橡皮筋框会作为普通块级元素插在 viewport 流里 —— 根本不可见。
   补了样式，并加 `.add` / `.sub` 两个状态类。
2. **框选和 TransformControls 抢pointerdown**。两边都在 canvas 上监听，
   拖gizmo 手柄移动实体会同时画出框选框，松手时 `commitBoxSelect` 把刚选中的实体改写成框里的那些。
   守卫判据用`transform.dragging`（TC 在第 176 行注册 pointerdown，比本文件早，拖到我们这里时已是 true），
   **不能用 `transform.axis`** —— axis 保留的是「上一次 hover」的轴，光标移开不会立刻清空，
   拿它当判据会让远离手柄的正常框选也被吞掉（实测 3 个用例直接不启动）。
   → 教训：判断「事件是否被别处接管」要用**该处的状态标志**，不要用「最近一次命中的缓存」。

### 测试踩的坑（4 个，全是测试 bug 不是产品 bug，但排查成本很高）
这一轮 21 个用例里有 8 个曾经失败，**没有一个是产品缺陷**，全部是测试的坐标假设错误。教训值得单列：

1. **视口左上角是视图立方体（`.vc-face`），不是 canvas。**
   从 `(vp.l+30, vp.t+25)` 起手会点到视图立方体 → 相机被切成正视图 → 后续所有屏幕坐标全失真。
   `elementFromPoint` 一查就现形。
2. **框的矩形一旦越出视口，pointerdown 落在 canvas 外（`elementFromPoint` 返回 null），框选根本不启动。**
   症状是「什么都没发生」而不是「选少了」，极易误判成产品坏了。
   `boxOver()` 现在会把结果 clamp 进视口，并在退化时 throw。
3. **实体尺寸/间距必须让投影分离，否则断言无法成立。**
   40mm 盒子在该相机下投影宽 255px，间距 50mm 只拉开 178px → 投影交叠
   （B1 404-659 / B2 557-843 / B3 759-1093），「只框住前两个」永远不成立。
   试过 X 横排（50/90/140mm）、Z 前后排（-90/0/90）、移动相机（拉到 z=150 反而因透视放大更宽，
   单格465px 直接溢出）全部失败。最终方案：**默认相机 + 20mm 实体（scale 0.5）+ 50mm 间距**，
   实测投影 [471,442,599,569] [631,493,772,644] [839,560,1006,744]，分离且全在视口内。
4. **起手点不能落在 gizmo 手柄上。** 单选/多选态下手柄就在实体附近，
   从包围盒左上角起手会被 TC 接管。**从左下角起手**即可绕开。
   `dragBox()` 现在会断言起手点命中 CANVAS#canvas，否则直接 throw 并报出实际命中的元素。

### 方法论：分不清是产品 bug 还是测试 bug 时，写探针脚本复算
连续 8 个失败、每次猜一个原因都错时，不再猜，直接写 `_probeN.mjs` 把

      先验证输入，再看逻辑。

## 第十三轮：选择系统**全量重写**（v13.mjs 27/27，累计 174/174）

### 重写前的实测结果（定位依据）
| 路径 | 重写前 |
|---|---|
| 单击 | 1 个 ✅ |
| **第一次 Shift+点击** | **仍 1 个 ❌** |
| 第二次 Shift+点击 | 2 个 ✅ |
| **拖多选 gizmo** | **3 个全不动 ❌** |

### 架构决策：唯一写入口
原来全项目 **70+ 处** `state.selection = ...` 直接赋值，散在点击/框选/粘贴/撤销/面板/删除/复制各路径。
每加一条路径就要手动同步 gizmo+标注+面板+对齐手柄，漏一处就出幽灵 bug。
现在全部收口到 `setSelection(ids, opts)`，配套 `selAdd/selRemove/selToggle/selClear/selAll/selOnly/revalidateSelection`。
赋值点从 27 处降到 2 处（都在 setSelection / sanitizeSelection 内部）。

### 核心机制：多选变换代理（selProxy）
TransformControls 天生只能操作**一个** Object3D → 多选时挂到一个不可见代理上：
- 代理摆在整组包围盒中心，`transform.attach(selProxy)`
- `captureSelItems()` 在 pointerdown 记录每个实体的初始pos/quat/scale
- `applyProxyDelta()` 每次 objectChange 用「代理当前值 − 起点值」算出增量分发给全部实体
- 旋转/缩放以**整组中心为支点**，平移是刚性平移
- 单选时代理中心与实体中心重合，行为与旧版一致

### 本轮修的 5 个真 bug
1. **Shift 首次必定失效**：`state.selection.slice(0, 1).concat(id)` 永远把选择集截断成「只剩第一个再补新 id」。
   正确写法是追加。同一bug在大纲面板 onClick 里还有第二份，一并修掉。
2. **TC 报 "attached 3D object must be a part of the scene graph"**：
   代理必须 `scene.add(selProxy)`（矩阵世界依赖父级链），再 `visible=false` 不参与渲染。
3. **尺寸标注挡住实体，多点不上**（最隐蔽的一个）：
   单选时视口里有 3 个 `.dim-tag`，经常正好压在相邻实体上，`elementFromPoint` 返回
   `DIV.dim-tag` 而不是 canvas → 实体明明在鼠标下面却收不到 click →
   症状是「点第二个没反应」「Shift 加不上第二个」。
   改 `.dim-tag { pointer-events: none }`（平时点穿透），**按住 Alt 时**加 `#dimLayer.dim-edit` 打开交互以编辑数值。
   提示条已更新说明 Alt 用法。
4. **拖动无法撤销**：`commitTransform()` 在 pointerup 才 `pushHistory()`，
   而 pushHistory 存的是**当前**状态 —— 那时物体已被移动过，存进历史的是「移动后」的快照。
   改为在 `dragging-changed` 的 **true 分支**（变换开始前）`beginTransform()` 抓快照，
   false 分支复位 `transformSnapTaken`。
5. **Ctrl+G 解不掉组**：已编组的实体再次 Ctrl+G 会套出一个新编组。
   `groupSelection()` 加互斥判断：若选中项全属同一编组则转调 `ungroupSelection()`。

### 多选视觉
- 多选 → `Box3Helper` 画**整组统一包围盒**（拖它整组移动，用户明确要求这个手感），
  同时隐藏旋转弧与尺寸标注
- 单选 → 旋转弧 + 尺寸标注（不变）

### 教训
- **「多选功能没了」不是单点bug，是架构问题**：写入口分散时，每条新路径都要手工同步4 处视觉，
  漏一处就复现「功能好像又没有了」。这种症状应该直接收口写入口，而不是逐个补。
- **症状「点某个实体没反应」要先查 `document.elementFromPoint`**：
  实体在鼠标下面 ≠ 事件能到达它，中间可能隔着任何 pointer-events:auto 的浮层。
  这一条花的时间最多，而查它只要一行。

### 踩的 4 个坑（都是 MutationObserver 相关，值得记）
1. **正则回调的参数传递不一致**：

2. **scan() 只处理 document.body 的直接文本节点** → 整棵子树的 title/aria 全漏。

   但页面就是没变化。改成 querySelectorAll 抓所有带属性元素 + TreeWalker 扫文本节点才解决。
3. **MutationObserver 自触发死循环**：翻译 title → 触发 attributes 回调 → 再翻译…
   浏览器检测到这种循环会**直接断开 observer**，表现为「一开始翻了几条，之后再也不生效」。
   必须用 selfMutating 标志自锁，并在 setTimeout(0) 里释放。
4. **词表里混进了坏字符**（`��角`），写入时损坏的。中文词条文件要注意编码。
