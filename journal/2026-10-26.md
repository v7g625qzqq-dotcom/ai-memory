### 关键决策：导出必须双根目录，单根会丢历史

**问题**：任务给的命令只扫 `--root "C:\Users\DELL\WorkBuddy"`，实跑后发现它把
`journal/2026-10-04/05/06/19/20.md` 和 `memory/MEMORY.md` 覆盖成了**内容更少的版本**，
git diff 显示 **527 行删除**——真实历史被静默抹掉。

**根因**：记忆分散在两个地方，而 `C:\Users\DELL\WorkBuddy` 只有 08-07 ~ 10-23 的日志；
**10-04 ~ 10-25 的最新日志其实在 `D:\360Downloads\2026-10-XX-XX-XX` 各工作区里**。
上一版导出（HEAD）同时用了两个根目录，所以文件更全。

**解法**：`merge_memory.py` 的 `--root` 是 `action="append"`，可多次传。
用 `find` 找出 `D:\360Downloads` 下所有含 `.workbuddy/memory` 的工作区，逐个追加为 `--root`：

```bash
PY="C:/Users/DELL/.workbuddy/binaries/python/versions/3.13.12/python.exe"
ARGS=(--out . --root "C:\Users\DELL\WorkBuddy" --copy-identity "C:\Users\DELL\.workbuddy\user-5b8d0854-1828-4f53-a5e6-d2bc92c698ad-personal")
while IFS= read -r d; do ARGS+=(--root "$d"); done < <(find "D:/360Downloads" -maxdepth 3 -type d -name memory -path "*.workbuddy*" | sed 's|/.workbuddy/memory$||' | sort)
"$PY" merge_memory.py "${ARGS[@]}"
```

**踩坑**：第一次用 `eval` 拼参数，`--root "C:\\Users\\DELL\\WorkBuddy"` 被反斜杠转义吃掉，
只扫到 D 盘那批（daily 18 天 / longterm 1 份），且覆盖了 C 盘那批的正确内容。
**改用 bash 数组 `ARGS+=(--root "$d")` 后正常**（daily 35 天 / longterm 2 份 / autos 1 份）。
→ 结论：**bash 传参一律用数组，不要用 eval + 字符串拼接**。

**校验方式**：合并后先 `git diff --stat`，必须确认是**纯增量**（只有 + 没有 -）。
本次 6 文件 671 行纯新增，0 删除，才允许提交。
